# MedTimeline

История здоровья из своих документов. Загружаете PDF анализов и фото бумажных заключений — ИИ вытаскивает из них показатели, собирает таймлайн и строит динамику.

## Запуск

Service worker и IndexedDB не работают с `file://`, поэтому нужен сервер — любой:

```bash
python3 -m http.server 8765
# открыть http://localhost:8765
```

## Как посмотреть без своих документов

Настройки → «Загрузить демо-историю». Заполнит ленту образцами анализов за 2019–2026: пять документов, тринадцать показателей, пять групп. Ключ не нужен.

## Вход

При регистрации после первых документов человек задаёт почту и пароль. Дальше история открывается только по паролю: «Выйти» в настройках запирает её, при следующем открытии спрашивается пароль.

Сервера у приложения нет, поэтому проверять пароль негде, кроме браузера. Храним не пароль, а PBKDF2-SHA256 от него — 210 000 итераций и случайная соль на пользователя, в IndexedDB рядом с документами. Проверка занимает около 90 мс.

**Что это даёт и чего не даёт.** Замок отсекает чужого человека, взявшего телефон: без пароля приложение не покажет ни одного документа. Но сами документы лежат в IndexedDB как есть, и через DevTools их видно. Настоящая защита — шифровать данные ключом из пароля (AES-GCM), но тогда забытый пароль означает потерю истории безвозвратно.

Восстановить пароль нельзя: писать некому и сравнивать не с чем. На экране входа есть только «Стереть историю и начать заново».

Если браузер не даёт Web Crypto (открыли по `http://` не с localhost), замок не ставится вовсе — карточка «Вход» в настройках просто не показывается.

## Как распознавать свои документы

Настройки → вставить ключ OpenAI (`sk-proj-...`) и при желании выбрать модель.

| Модель | Когда |
|---|---|
| `gpt-5.6-terra` | по умолчанию, баланс точности и цены |
| `gpt-5.6-luna` | вдесятеро дешевле, на чистых бланках качество то же |
| `gpt-5.6-sol` | если terra путается на плохих сканах |

Ключ лежит в `localStorage` этого браузера и уходит напрямую в `api.openai.com`. Мы его никуда не отправляем и на сервере не храним — сервера у приложения нет вообще.

**Это годится, пока ключ ваш собственный.** Для общего ключа так нельзя: он окажется виден каждому, кто откроет вкладку. Сама OpenAI прямо пишет в [Best Practices for API Key Safety](https://help.openai.com/en/articles/5112595-best-practices-for-api-key-safety), что запросы следует пускать через свой бэкенд. Если приложение будет раздаваться пользователям, распознавание нужно унести за Cloudflare Worker, где ключ лежит в секретах:

```js
// worker.js — набросок, в бой не пойдёт как есть
export default {
  async fetch(req, env) {
    if (req.method !== 'POST') return new Response('nope', { status: 405 });
    const upstream = await fetch('https://api.openai.com/v1/responses', {
      method: 'POST',
      headers: {
        'content-type': 'application/json',
        'authorization': 'Bearer ' + env.OPENAI_API_KEY   // wrangler secret put OPENAI_API_KEY
      },
      body: await req.text()
    });
    return new Response(upstream.body, {
      status: upstream.status,
      headers: { 'content-type': 'application/json', 'access-control-allow-origin': '*' }
    });
  }
};
```

Тогда в `extract.js` меняется только адрес и исчезает заголовок с ключом. Дальше нужен свой рейт-лимит, иначе за общий ключ заплатите вы.

## Решения, которые стоит знать

**Хранилище — IndexedDB, не localStorage.** В localStorage только строки и ~5 МБ на домен, а один скан заключения весит 3 МБ. Документы никуда не загружаются: лежат в браузере вместе с исходным файлом, поэтому его можно открыть из карточки.

**Эндпоинт — `/v1/responses`, ответ через `text.format` с `strict: true`.** Структурированный вывод по JSON-схеме, а не «попроси JSON и распарси» — иначе на каждом десятом документе прилетит текст вокруг скобок. PDF уходит блоком `input_file` с обязательным префиксом `data:application/pdf;base64,`, фото — блоком `input_image` с `detail: "high"` (на `low` бланк ужимается до 512 px и цифры не читаются). Фото ужимаются до 2048 px: выше OpenAI всё равно масштабирует сам.

**Ответ разбирается по массиву `output`, а не по `output_text`.** Поле `output_text` есть только в официальных SDK — в сыром HTTP-ответе его нет, это проверено. Плюс перед сообщением могут идти служебные элементы, поэтому ищем `output.find(o => o.type === 'message')`, а не `output[0]`, и проверяем блок `refusal` до `JSON.parse`.

**`reasoning.effort: 'low'`.** Извлечение по готовой схеме — не та задача, где нужны долгие размышления: качество то же, а ждать вдвое меньше. Один документ — примерно 4–5 секунд.

**Один показатель — одна серия, даже если лаборатории назвали его по-разному.** Три бланка щитовидной вернулись с «ТТГ», «ТТГ (тиреотропный гормон)» и «Тиреотропный гормон (ТТГ)» — буквальное сравнение имён рвало серию на три части, и график не появлялся. Имя разбирается на основную часть и часть в скобках, они сличаются крест-накрест. При этом «Глюкоза (натощак)» и «Глюкоза (после нагрузки)» остаются разными сериями: там скобка уточняет условие, а не расшифровывает название. Если в серии разные единицы, под графиком появляется предупреждение.

**Значение попадает на график, только если оно целиком число.** Иначе из «контроль через 3 месяца» получалась бы точка со значением 3.

**Дубликаты отсекаются до запроса в модель.** Разбор платный — сличать после отправки значит платить за уже разобранный файл.

**Все поля схемы обязательные, отсутствующие приходят пустой строкой.** В строгом режиме OpenAI не бывает необязательных полей: либо перечисляй в `required`, либо делай тип nullable. Пустая строка проще в разборе, чем `null`.

**Документы разбираются по одному, а не пачкой.** Медленнее, зато не упирается в лимит запросов и видно, на каком файле всё встало. Сбой одного файла не роняет остальные.

**Группы показателей приложение собирает само.** Захардкоженного списка систем организма нет: каждому показателю модель проставляет `system`, а приложение сводит их в чипы и считает документы. Появился анализ на витамины — появилась группа «Витамины и железо». Удалили последний документ группы — группа исчезла, в том числе из активного фильтра.

**Масштаб таймлайна линейный, с потолком.** 56 px на год, поэтому два года ровно вдвое длиннее одного. Выше 200 px высота упирается и промежуток помечается свёрнутым — иначе 29 лет до первого анализа заняли бы 1600 px. Потолок, а не сворачивание в маленький бейдж: так длинный разрыв никогда не окажется короче короткого.

**Даты собираются по частям.** `new Date('2019-05-12')` разбирается как UTC-полночь, и западнее Гринвича `getDate()` отдаёт предыдущий день. Поэтому везде `D()`, который собирает дату из компонентов.

## Чего пока нет

- Оплаты и нескольких профилей в аккаунте — они в `SPEC.md`, но главный сценарий должен сначала работать целиком
- Аккаунта на сервере: вход локальный, на другом устройстве истории не будет
- Шифрования истории — пароль закрывает вход, но не сами данные в IndexedDB
- Восстановления пароля — восстанавливать негде
- Экспорта истории и шаринга с врачом
- Повторного распознавания документа, если модель ошиблась целиком (можно удалить и загрузить заново)
