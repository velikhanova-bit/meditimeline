# ship-it — от localhost до живой ссылки

L1 дня: ссылка открывается с телефона постороннего человека. Не «работает у меня», не «на localhost:3000». Посторонний — любой, кроме автора продукта.

Скилл про веб. Нативный iOS идёт другим путём — TestFlight, скилл `/ios-app`, фаза 4.

## Порядок

### 1. Проверь, что деплой уже настроен

```bash
bash bin/ship url
```

Если печатает URL — переходи к шагу 3. Если ругается — шаг 2.

### 2. Первый раз

```bash
bash bin/ship init <имя-продукта>
```

Скрипт сделает git, создаст **публичный** репозиторий на GitHub, включит Pages, запушит и дождётся живого URL.

Прежде чем запускать, проверь глазами, что в папке нет секретов: `git status --porcelain` и `cat .gitignore`. Репозиторий публичный. Токены ботов, ключи платёжек и `.env` в него попасть не должны. `.env` в `.gitignore` уже есть — убедись, что он там реально лежит.

### 3. Каждый следующий раз

```bash
bash bin/ship
```

Коммитит, пушит, ждёт выката и проверяет, что URL отдаёт 200. Без этой проверки не говори «задеплоил».

## Что ломается чаще всего

**Белая страница, в консоли 404 на css/js.** GitHub Pages отдаёт сайт по адресу `/<repo>/`, а не с корня домена. Абсолютные пути ломаются.

```html
<!-- было -->  <script src="/app.js"></script>
<!-- стало --> <script src="./app.js"></script>
```

Все пути к своим файлам — относительные, начиная с `./`. Это же касается `fetch('/api/...')` и картинок.

**404 на всей странице.** Файл должен называться ровно `index.html` и лежать в корне репозитория. Не `Index.html`, не `src/index.html`.

**Изменения не видны.** Выкат идёт 1–3 минуты. Дальше — жёсткая перезагрузка (Cmd+Shift+R) или открыть в приватном окне. Проверить статус: `gh run list --limit 3`.

**Нужен серверный код** — база, приём вебхуков, скрытый API-ключ. GitHub Pages это не умеет, там только статика. Варианты по возрастанию трудозатрат:

1. Обойтись без сервера: `localStorage`, данные в JSON-файле рядом с сайтом.
2. Внешний сервис прямо из браузера — Google Forms, Airtable, Supabase.
3. Cloudflare Worker — см. `starters/tg-bot-worker`, там же живут вебхуки и секреты.

Не поднимай ради этого VPS. Это минус два часа.

**Ключ нельзя светить в браузере.** Если ключ попал в клиентский JS — он публичный, точка. Всё, что должно оставаться в секрете, живёт в Worker (`wrangler secret put`).

## Cloudflare Pages вместо GitHub Pages

```bash
bash bin/ship cf <имя-продукта>
```

Имеет смысл, когда нужен свой домен, редиректы или заголовки. В остальном GitHub Pages проще — не заводи второй аккаунт без нужды.

## Проверка на L1

Прежде чем сказать, что L1 закрыт:

1. `curl -sSI <url>` → `200`.
2. Открыть URL на телефоне, **не в своей сети** — с мобильного интернета.
3. Открыть в приватном окне: нет ли зависимости от твоего localStorage и залогиненности.
