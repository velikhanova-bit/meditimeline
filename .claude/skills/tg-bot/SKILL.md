# tg-bot — бот и серверная часть без сервера

Стартер: `starters/tg-bot-worker`. Cloudflare Worker — бесплатно, разворачивается одной командой, держит секреты. Это же единственное место в харнессе, где вообще можно хранить ключи: GitHub Pages раздаёт статику и всё, что там лежит, публично.

VPS сегодня не поднимаем. Это минус два часа и ничего не даёт.

## Порядок

### 1. Токен

`@BotFather` → `/newbot` → имя → username, оканчивающийся на `bot`. В ответ придёт токен вида `8123456789:AAH...`.

Токен — пароль от бота. Не в код, не в git, не в чат. Только `wrangler secret put`.

### 2. Поднять Worker

```bash
cp -r starters/tg-bot-worker ~/my-bot && cd ~/my-bot
npm install
npx wrangler login                    # откроется браузер, разреши доступ
npx wrangler secret put BOT_TOKEN     # вставь токен, он не покажется на экране
npx wrangler deploy
```

В конце напечатается URL вида `https://my-bot.<аккаунт>.workers.dev`. Это адрес вебхука.

### 3. Подписать бота на вебхук

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://my-bot.<аккаунт>.workers.dev/tg"
```

Ответ должен содержать `"ok":true`. Проверить, что реально подписалось:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

Смотри поле `last_error_message`. Если там что-то есть — вебхук не работает, сколько бы `ok:true` ни было при установке.

### 4. Написать боту

Напиши `/start` в чат. Ответ должен прийти за секунду. Если тишина — раздел «Что ломается».

## Дальше делаешь продукт

Вся логика — в `handleUpdate` в `src/worker.js`. Разбор апдейта и отправка сообщений уже написаны, дописывай ветки.

Полезное, что стоит знать сразу:

- **Кнопки.** `reply_markup: { inline_keyboard: [[{ text: 'Посчитать', callback_data: 'calc' }]] }`. Нажатие прилетает как `callback_query`, на него надо ответить `answerCallbackQuery`, иначе у человека крутится часик.
- **Состояние диалога.** Не держи в переменной модуля — Worker живёт от запроса до запроса, между вызовами переменная теряется. Либо KV, либо (быстрее) вообще без состояния: одна команда — один ответ.
- **Мини-апп.** Кнопка `web_app: { url: '<твой GitHub Pages URL>' }` открывает обычный сайт внутри Telegram. Это самый дешёвый способ сделать «приложение» за день: фронт на Pages, бот на Worker.

## Если нужен просто приём заявок с сайта

Бот не обязателен как продукт — Worker работает и как маленький бэкенд для формы. Отправляешь `POST /lead` с сайта, Worker пересылает в твой чат. В стартере это уже есть, включая CORS.

`chat_id` своего личного чата: напиши боту любое сообщение и открой
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` — поле `message.chat.id`.

## Что ломается

**Бот молчит, вебхук вроде стоит.** Смотри логи в реальном времени:

```bash
npx wrangler tail
```

Напиши боту и смотри, что печатается. Обычно там сразу видно исключение.

**`getWebhookInfo` показывает ошибку SSL или 404.** URL вебхука должен точно совпадать с путём, который обрабатывает Worker (`/tg` в стартере). Лишний или недостающий слэш ломает всё.

**Бот отвечает дважды.** Один токен подписан на два вебхука, или где-то параллельно запущен `getUpdates` (например, старый локальный скрипт). Один бот — один способ получения апдейтов. Останови лишнее.

**`401 Unauthorized` от Telegram API.** Секрет не установлен или установлен с пробелом. Проверь `npx wrangler secret list` и перезалей.

**Изменения не применились.** `npx wrangler deploy` после каждой правки. Worker не подхватывает файлы сам.

## Не делай сегодня

- Не бери aiogram, python-telegram-bot и прочие фреймворки: им нужен постоянно живущий процесс, а значит хостинг, а значит час на деплой.
- Не поднимай базу. JSON в KV или вовсе без хранения.
- Не делай админку, платежи внутри бота и мультиязычность.
